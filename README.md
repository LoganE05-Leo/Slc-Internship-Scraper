# slc-internship-scraper

Scans ~60 Salt Lake City-metro companies for internship postings by calling
each employer's applicant-tracking system (ATS) JSON API directly — no
JavaScript-rendered careers-page scraping. Highlights Fall 2026 postings and
emails you only the postings that are new since the last run. Runs on GitHub
Actions Monday/Wednesday/Friday.

## How it works

1. **`config/companies.yaml`** lists ~60 companies with a best-guess
   `careers_url` and `ats: auto`.
2. **`detect_ats.py`** visits each `careers_url`, follows redirects, and
   regex-matches the final URL + HTML against known ATS signatures
   (Greenhouse, Lever, Ashby, SmartRecruiters, Workable, Workday). Results
   are written to `config/companies.resolved.yaml`.
3. **`python -m src.main`** loads the resolved company list (falling back to
   `companies.yaml` if you haven't run `detect_ats.py` yet), fetches
   postings from each company's ATS API (or a generic HTML fallback if no
   ATS was detected), filters for internships/co-ops in the SLC area, dedups
   against `data/seen_jobs.json`, writes `reports/latest.md`, appends it to
   the GitHub Actions step summary, and emails new postings via SMTP.

A failure fetching one company is logged and skipped — it never aborts the
whole run.

## Setup

1. Install dependencies:

   ```bash
   pip install -r requirements.txt
   ```

2. Resolve each company's ATS once (re-run any time you add companies or a
   company migrates ATS providers):

   ```bash
   python detect_ats.py
   ```

   This writes `config/companies.resolved.yaml`. Commit it — `src/main.py`
   prefers it over `companies.yaml`.

3. Do a local test run:

   ```bash
   python -m src.main
   ```

   Check `reports/latest.md` for output. Without SMTP env vars set, no email
   is sent — the report is just written to disk.

4. **Add GitHub Actions secrets** (repo Settings -> Secrets and variables ->
   Actions) so the scheduled workflow can email you:

   | Secret        | Example                          |
   | -------------- | --------------------------------- |
   | `SMTP_HOST`   | `smtp.gmail.com`                  |
   | `SMTP_PORT`   | `465` (default if unset)          |
   | `SMTP_USER`   | `you@gmail.com`                   |
   | `SMTP_PASS`   | an app password, not your login   |
   | `EMAIL_TO`    | `you@gmail.com` (comma-separated for multiple) |

   If any of `SMTP_HOST`/`SMTP_USER`/`SMTP_PASS`/`EMAIL_TO` are missing, the
   workflow still runs and updates the report — it just skips sending mail.

5. Push to GitHub. The workflow at
   [.github/workflows/scrape.yml](.github/workflows/scrape.yml) runs
   Mon/Wed/Fri at 14:00 UTC (`workflow_dispatch` also lets you trigger it
   manually from the Actions tab) and commits `data/seen_jobs.json` +
   `reports/latest.md` back to the repo so dedup state persists between runs.

## Configuration (env vars)

- **`FILTER_MODE`** (default `internship`):
  - `internship` — keep every internship/co-op match; Fall 2026 ones are
    starred in the report. This is the default because ATS list endpoints
    often omit job descriptions, so a strict season filter would silently
    drop real postings.
  - `fall2026` — keep only postings that explicitly mention Fall/Autumn 2026.
  - `year2026` — keep postings that mention 2026 in any form.
- **`LOCATION_KEYWORDS`** (comma-separated, default covers Salt Lake City,
  Sandy, Draper, Lehi, Murray, South Jordan, West Valley, Cottonwood
  Heights, Midvale, West Jordan, and Remote) — only postings whose location
  contains one of these are kept; postings with an unknown/blank location
  are always kept.

## Project layout

```
config/companies.yaml            seed list (~60 companies, ats: auto)
config/companies.resolved.yaml   generated by detect_ats.py
detect_ats.py                    ATS auto-detection CLI
src/main.py                      orchestrates fetch -> filter -> dedup -> report -> email
src/filters.py                   internship/co-op regex, Fall-2026 tagging, FILTER_MODE/LOCATION_KEYWORDS
src/state.py                     data/seen_jobs.json dedup (sha1 of URL, 60-day prune)
src/report.py                    reports/latest.md generation
src/emailer.py                   SMTP delivery
src/fetchers/                    one module per ATS (greenhouse, lever, ashby,
                                  smartrecruiters, workable, workday) + generic_html fallback
tests/test_filters.py            unit tests for the filter logic
.github/workflows/scrape.yml     Mon/Wed/Fri cron + workflow_dispatch
```

## Adding a company

Add an entry to `config/companies.yaml`:

```yaml
- name: Example Co
  careers_url: https://www.example.com/careers
  ats: auto
```

Then re-run `python detect_ats.py` and commit the updated
`companies.resolved.yaml`.

## Running the tests

```bash
python -m unittest discover -s tests
```
